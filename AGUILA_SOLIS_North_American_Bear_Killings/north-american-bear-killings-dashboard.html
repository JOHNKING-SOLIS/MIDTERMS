Preprocessing workflow

Project workflow and decision rules represented in the notebook.

13 stages
01

Load dataset

Load the supplied CSV and confirm row and column counts.

02

Inspect structure

Review sample rows, column names, data types, summaries, and unique values.

03

Check missing values

Trim text, normalize spaces, convert blank strings to missing values, fill missing gender as Unknown.

04

Check duplicates

Count exact duplicate rows and remove duplicates if any are present.

05

Correct data types

Standardize column names, convert age to numeric, parse dates, and align month/year to valid dates.

06

Detect age outliers

Apply the IQR rule; flag unusual ages for review instead of deleting historical records automatically.

07

Engineer features

Create incident month, year, decade, and season from valid dates.

08

Encode categories

One-hot encode gender, incident type, and bear type in the model-ready table.

09

Scale numerical data

Standardize age with StandardScaler when enough valid age values are available.

10

Save outputs

Save a readable cleaned dataset and a separate model-ready dataset.

11

Validate results

Reload the saved CSV, compare shapes, check duplicates, missing values, and selected data types.

12

Create 10 charts

Generate all ten visualizations from the cleaned records.

13

Finish

Review the dashboard and retain notes on source and data limitations.

Quality checks & project objectives

What the notebook is designed to verify and deliver.

Validation checklist

  • ✓Compare original, cleaned, and reloaded CSV shapes.
  • ✓Check duplicate rows after cleaning.
  • ✓Inspect remaining missing values and selected data types.
  • ✓Keep age outliers flagged for review instead of deleting them automatically.
  • ✓Save the readable cleaned data and separate model-ready data.

These are the notebook’s planned checks. The browser dashboard does not claim that a new CSV has passed the Python notebook’s save-and-reload validation.

Project objectives

  • 01Inspect structure, data types, missing values, and duplicates.
  • 02Clean text fields and convert columns to suitable data types.
  • 03Detect unusual numeric values without automatically deleting meaningful historical cases.
  • 04Create date-based features, encode selected categories, and scale a numerical feature for modeling.
  • 05Save and validate the cleaned dataset and produce exactly ten visualizations.
Interpretation reminder: these are recorded incidents in a compiled dataset. Counts alone do not establish the probability of an encounter or comparative risk; exposure and population context are not included here.
